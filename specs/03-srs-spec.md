> Дата: 2026-09-27. Статус: черновик v1 (M1).
> Ссылки: plan://M1#3 · research/01-research.md §7 · research/03-methods-and-exercises.md §1, §7 · research/00-summary.md.
> Адресация: `spec://com.sahacky.hunter-english/specs/03-srs-spec.md#<якорь>`, внутри документа — короткие ID `srs://…`.

## 1. Обзор {#overview}

`srs://overview` — SRS — ядро закрепления всего курса: слова, фразы уроков, цитаты, разговорник проходят через один планировщик на базе **FSRS** (библиотека **`ts-fsrs`**). Целевой retention **0,90** (дефолт FSRS): выше 0,95 нагрузка растёт непропорционально (03 §1).

Принципы:
1. Алгоритм не пишем сами — используем `ts-fsrs` как есть.
2. Каждый ответ пишется в append-only лог `review_log` (нужен для статистики и будущей оптимизации параметров, research/07).
3. Всё, что видит пользователь (интервалы, «сила» слова), выводится из состояния FSRS, без ручных статусов.

## 2. Библиотека ts-fsrs и параметры {#ts-fsrs}

`srs://ts-fsrs` — используем официальный пакет `ts-fsrs` (open-spaced-repetition), версия фиксируется в `package.json` при M4.

| Параметр | Значение | Комментарий |
|---|---|---|
| `request_retention` | **0.90** | целевая вероятность вспомнить при показе |
| `maximum_interval` | 36500 | потолок интервала, дней |
| `enable_fuzz` | true | случайный разброс интервалов, чтобы повторы не сбивались в день |
| `enable_short_term` | true | минутные интервалы в Learning/Relearning (шаги, см. srs://steps) |
| `learning_steps` | — (не задаётся) | ts-fsrs 4.x **не конфигурирует шаги**: при `enable_short_term` библиотека ведёт их сама (New: Again 1 м / Hard 5 м / Good 10 м; шаг Relearning 5 м). Синхронизировано с фактом 4.7.1 (REVIEW-маркер в `scheduler.ts`) |
| `relearning_steps` | — (не задаётся) | см. выше — шаг задан библиотекой, не параметром |
| веса `w` | дефолтные (FSRS-5/6) | вручную не крутим; оптимизация по `review_log` — возможное будущее, не MVP |

Поля карточки, которые храним (полное соответствие модели `Card` в ts-fsrs):

| Поле | Тип | Смысл | Хранение (Dexie / Supabase) |
|---|---|---|---|
| `due` | Date | когда показать следующий раз | ISO-строка UTC / `timestamptz` |
| `stability` | number | стабильность памяти (дни до забывания с P=90%) | `numeric` |
| `difficulty` | number | сложность карточки, шкала 1–10 | `numeric` |
| `elapsed_days` | integer | дней с прошлого повторения | `int` |
| `scheduled_days` | integer | назначенный интервал | `int` |
| `reps` | integer | всего повторений карточки | `int` |
| `lapses` | integer | сколько раз «Не вспомнил» в состоянии Review | `int` |
| `state` | 0–3 | New / Learning / Review / Relearning | `smallint` |
| `last_review` | Date \| null | момент последнего повторения | ISO UTC / `timestamptz` |

Служебные поля приложения (рядом с моделью ts-fsrs, саму модель не смешиваем): `card_id` (PK), `note_id`, `type` (см. srs://card-types), `deck` (слова / фразы / цитаты / разговорник), `created_at`, `updated_at`, `suspended` (выключенная вручную карточка), `cloze_index` (только для cloze).

Вызовы: `createEmptyCard()` при создании, `fsrs(params).next(card, now, rating)` после ответа, чтение `RecordLogItem.card` — новое состояние, `RecordLogItem.log` — запись в `review_log`.

## 3. Типы карточек {#card-types}

`srs://card-types` — шесть типов (01 §7). Тип определяет только форму показа и проверки; планирование одинаковое.

| # | Тип (id) | Фронт → бэк | Проверка | Метод |
|---|---|---|---|---|
| 1 | `en-ru` | слово/фраза EN → перевод RU (выбор/самопроверка) | самопроверка + кнопка | узнавание |
| 2 | `ru-en` | RU → ввод EN текстом | нормализация + варианты, 03 §3 | припоминание (главный) |
| 3 | `dictation` | аудио (en-GB) → написать услышанное | как `ru-en`, опечатки по правилам 03 §3 | диктант |
| 4 | `cloze` | цитата с пропуском «Winter ___ coming.» → ввод | точное совпадение слова | recall в контексте |
| 5 | `speak` | RU (или EN-подсказка) → сказать в микрофон | распознанный текст vs эталон, зачёт при ≥80–85% совпадения слов | речь |
| 6 | `grammar` | фраза из урока RU → EN (ввод/голос) | как `ru-en` | production (Бебрис) |

Правило заметок:

| ID | Правило |
|---|---|
| `srs://rule-1` | **Из одной заметки — максимум 4 карточки.** Заметка «слово»: `en-ru` → `dictation` → `ru-en` → `speak`. Заметка «фраза урока» (тип `grammar`): `ru-en` → `dictation` → `speak`. Заметка «цитата»: `cloze` → `dictation`. Карточки создаются постепенно, не все сразу (см. srs://rule-2 и srs://limits). |
| `srs://rule-2` | **Пассив → актив.** Сначала карточка живёт пассивно (`en-ru` + звук). Обратные (`ru-en`, `speak`) «просыпаются», когда интервал пассивной карточки достигает **≥ 7 дней**. Пробуждённая карточка входит в очередь как новая и **не расходует** дневной лимит новых, но не более **5 пробуждений в день** (иначе пик нагрузки). |

Новые карточки всегда идут вперемешку по колодам (interleaving): ~10 слов + ~5 фраз/цитат за день.

## 4. Нагрузка и лимиты {#limits}

| ID | Правило |
|---|---|
| `srs://rule-3` | **15 новых карточек в день** (~10 слов + ~5 фраз). Настройка в профиле: 5–50, дефолт 15. При 15 новых → ~150 повторов/день ≈ 18–20 мин (03 §1). |
| `srs://rule-3a` | **Кап слов ≤10/день ИЗ ПОЛОСЫ РАНГА** (v2 V.6 + U3.2): новые карточки колоды `words` — только слова полосы текущего ранга (RANK_WORD_TARGET: E≤300/D≤1000/C≤1800/B≤2800/A≤4000/S≤5000, субтитровые — на S), не больше 10 в день (ёмкость SRS на слово ~×4 повторов); остаток лимита добирается фразами/цитатами/разговорником. Фильтр и кап — до интерливинга (buildQueue allowNew + WORDS_NEW_DAILY_CAP), порядок внутри колоды — created_at/card_id. На карточке слова — бейдж «Полоса ранга X» (связь с уроками ранга). |
| `srs://rule-4` | **Правило 10×N** (Anki): N новых в день дают ≈ 10×N повторов в устоявшемся режиме. Используется для прогноза нагрузки и предупреждений при смене лимита. |
| `srs://rule-5` | **Защита от завала.** Долг = карточки due на начало дня (без новых). Лимит новых на день: долг ≤ 50 → 15; 51–120 → 8; 121–200 → 4; > 200 → 0 + красное окно «Нагрузка снижена» и режим «только повторы». Отключается вручную в настройках (с предупреждением). |
| `srs://limits-review` | Жёсткого лимита повторов нет; сессия делится на блоки по 20 с промежуточным итогом. Кнопка «Закончить» доступна всегда, каждый ответ сохраняется сразу. |
| `srs://limits-new` | Пробуждённые обратные карточки (srs://rule-2) — не более 5/день, сверх лимита новых. |

## 5. Состояния и переходы {#states}

`srs://states` — жизненный цикл: `new → learning → review → relearning → review…`

| Из | Событие | В | Интервал |
|---|---|---|---|
| New | показ, оценка | Learning | минуты (шаг 1) |
| Learning | «Не вспомнил» | Learning | повтор текущего шага |
| Learning | «Вспомнил» на последнем шаге | Review | первый дневной интервал (считает FSRS) |
| Review | «Не вспомнил» (Again) | Relearning | шаг 5 мин (шаг библиотеки) |
| Review | Hard / Good / Easy | Review | FSRS-интервал |
| Relearning | «Не вспомнил» | Relearning | повтор шага 5 мин |
| Relearning | «Вспомнил» | Review | FSRS-интервал |

`srs://steps` — минутные шаги задаёт **сама библиотека** при `enable_short_term` (ts-fsrs 4.x: New — Again 1 м / Hard 5 м / Good 10 м; шаг Relearning — 5 м; параметры `learning_steps`/`relearning_steps` в API отсутствуют — синхронизировано с фактом 4.7.1). Внутри дневных шагов планирование ведёт приложение (минутные интервалы поверх `enable_short_term`, srs://ts-fsrs). Шаги не «сгорают» на конец дня: карточка с due в прошлом показывается первой при следующем открытии.

Young / mature: young — интервал < 21 дня, mature — ≥ 21. Порог влияет только на порядок и окраску.

## 6. Кнопки оценки {#buttons}

`srs://buttons` — маппинг в `Rating` ts-fsrs: Again=1, Hard=2, Good=3, Easy=4.

**Новичок (по умолчанию), 2 кнопки:**

| Кнопка | Клавиша | Rating | Learning | Review |
|---|---|---|---|---|
| «Не вспомнил» | 1 | Again (1) | повтор шага | уходит в Relearning |
| «Вспомнил» | 2 | Good (3) | следующий шаг / выпуск | обычный интервал |

**Продвинутый режим (4 кнопки), включается в настройках** (research/06 §4.4): Again=1 / Hard=2 / Good=3 / Easy=4. Кнопка Again визуально отделена (красная). Подпись следующего интервала над кнопками — включаемая. Переключение режима не меняет накопленное состояние карточек.

Дополнительно: «Показать ответ» — пробел; повтор аудио — R; медленно — S. В простом режиме подпись «Hard/Easy можно включить в настройках» — один раз, ненавязчиво.

## 7. Порядок сессии, день обучения, часовой пояс {#session-order}

`srs://session-order` — порядок очереди в течение дня:

1. **Learning/Relearning** — всё, чей минутный due наступил (внутри сессии очередь обновляется на лету).
2. **Review** — сначала young, потом mature; внутри — по возрастанию `due` (сначала просроченные).
3. **New** — в конце, в пределах дневного лимита (srs://rule-3, rule-5).

Счётчики как в Anki, цветом: «учу» (красный), «к повторению» (зелёный), «новые» (синий).

### Интерливинг-политика {#interleaving-policy} (план {#teaching-quality} Q1.4)

**Chunk-карточки со слотом** (план {#teaching-quality} Q2.2, research/10 02 §3 №6): фразы-«скелеты» речи (`I'd like to ___ a table.`, `Could you tell me where ___ is?`) размечаются в данных полем `chunk_slot` (~200 шт.: разговорник + фразы уроков; без коллокационных списков — Kaufmann №24). Карточка типа `chunk` создаётся вместе с первой карточкой заметки, но **не расходует дневной лимит новых** (srs://rule-3/5 не трогаются): до зрелости note она остаётся New вне fresh-очереди и просыпается через rule-2 (mature-сиблинг, ≤5/день). Фронт — шаблон со слотом `___`, бэк — слот + вся фраза + перевод.

1. **Между колодами — интерливинг есть**: новые карточки сводятся в очередь round-robin'ом по колодам в фиксированном порядке `words → phrases → quotes → phrasebook` (реализация — `interleaveByDeck`, домен). Межкатегорийное чередование улучшает различение похожих элементов (interleaving-эффект).
2. **Внутри колоды слова НЕ перемешиваются**: порядок = `created_at`, затем `card_id` — детерминированно, без RNG. Случайное перемешивание внутри категории ухудшает запоминание (Brunmair & Richter, 2019: g ≈ −0.39 против блокового/упорядоченного предъявления). Не «чинить» на Math.random.
3. **Детерминированность — часть контракта**: очередь новых воспроизводима на том же входе (восстановление сессии, чекпоинты, e2e). Гард-тест: `scheduler.test.ts` «интерливинг-политика…».
4. Диктант/построение (урочные интерливинг-вставки `interleave: true`) — отдельная механика урока, specs/02 {#interleaving}; на SRS-очередь не влияют.

`srs://day-boundary` — **день обучения: граница суток в 4:00 по локальному времени** (решение). Всё, что сделано до 4:00, считается предыдущим днём: ночные занятия после полуночи не «съедают» новый день и не ломают лимиты/стрик. Эта же граница используется геймификацией (game://streak, game://quests) и XP-капами (game://xp-caps).

`srs://timezone` — все `due`/`last_review` хранятся в **UTC**; «локальный день» вычисляется по часовому поясу профиля (IANA-имя, автоопределение с подтверждением). Междневные переносы: карточка с due «вчера по 4:00» просто попадает в начало очереди; никаких автоматических переносов и скрытия долга — кроме урезания новых по srs://rule-5.

## 8. Замер прогресса: мини-тесты словаря {#vlt}

`srs://vlt` — по мотивам Vocabulary Levels Test (Paul Nation), 03 §7.

- Триггер: каждые **~500 слов**, вошедших в статус «знаю» (state=Review и интервал ≥ 21 дня). Итоговые пороги: ~500, ~1000, ~1500, ~2000, ~2500, ~3000, далее каждые 500.
- Формат: 20 заданий «слово → выбери значение из 6»; слова — случайная выборка из пройденных частотных полос: 1–719 (NGSL-Spoken), 720–2806 (NGSL), 2807–5000 (FrequencyWords).
- Результат: «ты знаешь ~X слов ≈ Y% разговорной речи» (+ история результатов в профиле). Награда: +40 XP (game://xp-table). На ранг не влияет — ранг только через Врата.
- Внешняя сверка для интереса: vocabularysize.com, с ранга B (ссылка, не интеграция).

## 10. Edge cases {#edge-cases}

| ID | Случай | Поведение |
|---|---|---|
| `srs://case-week-skip` | Пропуск недели | Ничего не удаляется и не переносится автоматически. Все due доступны, сессия блоками по 20. Новые — по srs://rule-5 (скорее всего 0) до рассасывания долга. Learning-карточки с истёкшими шагами — в начало очереди. Интервалы после пропуска пересчитает FSRS сам (elapsed_days честный). |
| `srs://case-clock-back` | Перевод часов назад / перелёт на запад | `due` в UTC — не ломается. Локальный день удлиняется: занятия остаются «вчерашним» днём до 4:00, лимиты/стрик не задваиваются (учёт по локальному дню обучения, srs://day-boundary). |
| `srs://case-clock-forward` | Перелёт на восток / смена пояса | Локальный день может укоротиться; 4:00-граница сглаживает. Смена пояса — в настройках, вручную; автоопределение предлагает изменение, но не применяет молча. |
| `srs://case-import-export` | Импорт/экспорт | Файл JSON v1: profiles + card_states + review_log + lesson_progress + user_stats + item_progress. Merge по `card_id`: побеждает запись с более поздним `last_review`/`updated_at`. `review_log` — дедуп по `id`, конфликты невозможны (append-only). Несовместимая версия формата — явная ошибка, тихий импорт запрещён. |
| `srs://case-suspend` | «Не хочу это слово» | `suspended=true`: карточка исключается из очереди, состояние сохраняется. Вернуть можно из словаря. В XP и статистике не участвует. |
| `srs://case-fsrs-upgrade` | Обновление версии ts-fsrs / весов | Старые состояния валидны (поля стабильны). Миграция — отдельная задача с бэкапом-экспортом; весов по умолчанию не касаемся. |

## 11. Открытые вопросы {#open-questions}

1. Порог young/mature 21 день (дефолт Anki) — оставить или 30?
2. «Пробуждение» обратных карточек не расходует лимит новых (≤5/день) — решение на бумаге; пересмотреть после первого месяца практики.
3. Пороги flood-guard (50/120/200) — первичные, откалибровать по ощущениям.
4. Мини-тест VLT: точная частота (ровно 500 «знаемых»?) и сложность дистракторов в 6 вариантах — уточнить при реализации контента.
5. Нужен ли показ стабильности/сложности пользователю в «детальной» карточке слова или только цветовая «сила» (research/06 §4.5)?
