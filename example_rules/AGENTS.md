# The Weakest Link — Проектная документация

## Концепция

Некоммерческая браузерная мультиплеерная игра-викторина, вдохновлённая кастомной картой Warcraft 3 "The Weakest Link" (автор Brian Deksnys).

Игроки слушают голосовые реплики персонажей из игр и угадывают, какому персонажу принадлежит озвучка, кликая на его иконку. Кто угадал быстрее и точнее — получает больше очков. По итогам раундов определяется "слабое звено".

## Целевая аудитория

Личный проект для семьи (2+ игрока). Не публикуется, не коммерческий.

## Стек технологий

- **Backend:** Ruby on Rails
- **Realtime:** Action Cable (WebSocket)
- **Frontend:** Hotwire (Turbo Streams + Stimulus)
- **Звук:** HTML5 Audio API (через Stimulus-контроллер)
- **Тесты:** RSpec

## Архитектура

### Сервер

- Хранит все звуковые файлы и иконки
- Отдаёт звуки через анонимный endpoint (например `/game/sound?token=abc123`) — клиент не знает, какому персонажу принадлежит звук, чтобы исключить жульничество
- Токен одноразовый, привязан к текущему раунду
- Является арбитром: фиксирует время ответа каждого игрока и определяет, кто кликнул первым
- Управляет логикой раундов, подсчётом очков, выбыванием

### Синхронизация звука

1. Сервер выбирает персонажа и отправляет всем клиентам анонимный URL звука
2. Клиенты скачивают звук и отправляют серверу `ready`
3. Когда **все** игроки прислали `ready` — сервер шлёт команду `play`
4. Все клиенты воспроизводят звук одновременно

### Клиент

- Отображает сетку иконок персонажей
- Воспроизводит звук по команде сервера (Stimulus-контроллер + Audio API)
- Отправляет серверу клик по иконке с меткой времени
- Получает обновления UI через Turbo Streams (очки, таймеры, результаты)

## Правила игры (по оригинальной карте v1.02)

### Иконки
- По умолчанию все доступные иконки видны сразу (~40–60 штук)
- Сгруппированы по расам/фракциям
- Герои отделены от обычных юнитов
- Пул звуков >100, каждый вопрос — рандомный выбор
- Хост МОЖЕТ настраивать количество отображаемых иконок при создании игры (отличие от оригинала)

### Раунды
- Игра идёт до победителя (пока не останется 1 человек)
- В каждом раунде 8–15 вопросов (звуков)
- После раунда — подсчёт, слабое звено вылетает (наименьшее количество очков + ошибки)
- При 6–10 игроках обычно 5–9 раундов

### Система очков
- Первая попытка правильная → **+3 очка**
- Вторая попытка правильная → **+2 очка**
- Третья и далее → **+1 очко**
- Неправильный клик → **–1 очко** (можно кликать сколько угодно)
- При ничьей — тай-брейк (speed round): первый правильный клик побеждает

### Repeat
- Игрок может запросить повтор звука (команда `-repeat`)

### Выбывание
- Выбывший игрок остаётся как спектатор
- Может продолжать кликать для фана (очки не влияют на победу)
- Фраза: "You are the weakest link… goodbye!"

### Режимы
- **Normal** — стандартные голосовые реплики
- **Expert** — включает "pissed"-звуки (после 3–4 кликов по юниту в WC3, они смешнее и сложнее)

## Паки (разделы)

Механика универсальная, данные разные. Структура паков:

```
/packs
  /warcraft3
    config.json    — список персонажей, пути к иконкам и звукам
    /icons
    /sounds
      /ru          — русская озвучка
      /en          — английская озвучка
  /starcraft2
    config.json
    /icons
    /sounds
      /ru
      /en
```

Иконки общие для всех локалей (персонаж выглядит одинаково). Звуки разделены по локалям — один и тот же персонаж, разная озвучка.

Добавить новую игру = создать папку с иконками, звуками и конфигом.

## Количество игроков

2+ (без жёсткого ограничения). Все подписаны на один Action Cable канал.

## Примечания

- Звуковых файлов ~700 МБ — предзагрузка на клиент невозможна, звуки отдаются по одному с сервера
- P2P отвергнут: сервер нужен как арбитр (определяет кто кликнул первым) и для защиты от жульничества

## Правила работы: WAL.md

В корне проекта ВСЕГДА поддерживается файл `WAL.md` (Write-Ahead Log). Это "сейвпоинт" для AI-сессии — инструкция для следующей сессии, чтобы продолжить работу без потери контекста.

### Начало сессии

**В начале каждой новой сессии** — первым делом прочитать `WAL.md` и `PLANS.md`, чтобы понять текущее состояние проекта, что было сделано, и что делать дальше. Не начинать работу, пока не ознакомился с обоими файлами.

### Когда обновлять

1. **В конце каждой сессии** — без исключений. Явное ("на сегодня всё") или по команде "обнови WAL".
2. **Перед деструктивной операцией** (рефакторинг, значительные изменения) — как checkpoint.
3. **При переключении контекста** на другой модуль — обновить WAL текущего модуля перед переключением.
4. **Превентивно при большом контексте** — если сессия длинная и контекст растёт, обновлять WAL промежуточными чекпоинтами, не дожидаясь краша.

### Формат

- До 3000 токенов. Завершённые элементы коллапсировать в одну строку.
- Содержит: что делать дальше, где делать, что НЕ трогать, какие решения ждут, какие тесты запустить.
- Анти-инструкции ("Watch out: не трогать X") критически важны — защищают от AI-поведения "я вижу что можно улучшить".
- НЕ история, НЕ отчёт — только то, что нужно следующей сессии для продолжения работы.

## Правила работы: PLANS.md

В корне проекта поддерживается файл `PLANS.md` — роадмап реализации, разбитый на майлстоуны.

### Правила

1. **PLANS.md — единственный источник правды** о том, что нужно сделать. Все задачи фиксируются здесь.
2. **Чекбоксы** — каждая задача имеет `[ ]` (не сделано) или `[x]` (сделано). Отмечать задачу выполненной сразу после завершения.
3. **Порядок майлстоунов** — выполнять последовательно. Не начинать следующий, пока текущий не завершён (если не согласовано иное).
4. **Изменения в плане** — если по ходу реализации выясняется, что план нужно изменить (новые задачи, изменение порядка) — обсудить с пользователем и обновить PLANS.md.
5. **Не придумывать задачи** — делать только то, что записано в PLANS.md или явно согласовано.

## Локализация (i18n)

- **Дефолтная локаль:** русский (`ru`)
- **Дополнительная локаль:** английский (`en`)
- Используется стандартный Rails i18n (locale-файлы `config/locales/ru.yml`, `config/locales/en.yml`)
- Интерфейс игры полностью локализован
- Звуки в паках разделены по локалям (`/sounds/ru/`, `/sounds/en/`)
- Иконки общие для всех локалей
- При создании игры хост выбирает локаль звуков

## Правила языка

- **Документация (.md файлы)** — всегда на русском языке.
- **Git-коммиты** — всегда на английском языке.
